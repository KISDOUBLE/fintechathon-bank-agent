# 令行 · 银行 AI 智能体

> 仓库：https://github.com/KISDOUBLE/fintechathon-bank-agent

一个**不会乱动钱**的银行智能体：自然语言进来，受权限约束的确定性执行出去。

- 大模型只负责**理解与提议**，不持有账户凭证，也不能发起资金动作。
- 每一笔资金动作在**工具执行层**独立鉴权，提示词无法绕过。
- 每个颜色判定都能说出**规则名 + 具体阈值**。
- 全链路审计用**哈希链**，改一条记录会断链。

零第三方依赖，只用 Node.js 内置模块（`node:sqlite` / `node:http` / `node:crypto` / `node:test`）。断网可跑，干净机器可起。

## 架构（请求经过的顺序）

```
渠道（Web / webhook）
  → 输入护栏      归一化（全角/零宽）+ 注入检测
  → 意图解析      规则优先，置信度不足才问模型
  → 三色判定      纯函数，只读快照，输出 rule + detail
  → 权限分级      L0/L1/L2/L3/X，金额与新设备会抬升
  → 人工确认      L2 二次确认，L3 多因子（演示用模拟验证码）
  → 工具层执行    再次鉴权，复式记账，幂等键
  → 审计          结构化 + 哈希链
```

### 三色判定：颜色是执行策略

| 颜色 | 含义 | 行为 |
| :--- | :--- | :--- |
| 绿 | 纯查询 | 直接执行 |
| 黄 | 日累计 ≤ ¥1,000 | 二次确认 |
| 红 | 日累计 > ¥1,000 | **多因子后放行**，不是拒绝 |
| 硬拦截 | 越限/越权/注入/熔断 | 直接拒绝 |

规则与阈值：

| 维度 | 规则 | 默认阈值 |
| :--- | :--- | :--- |
| 日累计额度内 | `R-AMT-YELLOW-CONFIRM` | ≤ ¥1,000 |
| 日累计超额 | `R-AMT-RED-VERIFY` | > ¥1,000 |
| 单笔硬上限 | `R-LIMIT-SINGLE-BLOCK` | ≥ ¥50,000 |
| 日累计硬上限 | `R-LIMIT-DAILY-BLOCK` | > ¥20,000 |
| 首次收款人 | `R-PAYEE-FIRST` | ≥ ¥500 |
| 可逆性 | `R-IRREVERSIBLE` | 转账、取消订阅 |
| 频次 | `R-FREQ-10M-WARN` / `R-FREQ-24H-BLOCK` | 10 分钟 >3 笔 / 24 小时 >5 笔 |
| 终端 | `R-DEVICE-NEW` | 新设备 2 小时内 |
| 熔断 | `CIRCUIT-OPEN` | 10 分钟内连续 3 次失败 |

任一硬拦截 → 拒绝；红色 → 多因子；黄色 → 确认；全绿 → 直接执行。

### 权限分级

| 级别 | 判定 | 本项目的实现 |
| :--- | :--- | :--- |
| L0 | 公开信息 | 汇率查询 |
| L1 | 本人只读 | 余额、流水、账单、订阅列表 |
| L2 | 本人中风险写 | 普通转账（≤ ¥1,000 日累计）、取消订阅 |
| L3 | 本人高风险写 | 判定为红色（> ¥1,000 日累计）的转账、新设备写操作 |
| X | 越权/跨域 | 跨用户访问、未知工具、超硬上限 |

关键点：`authorize()` 在 `ToolRegistry.execute()` 里被**再执行一次**。即使有人绕过对话层直接调用工具，`confirmed: false` 或 `mfaVerified: false` 依然会被拒绝。

## 防幻觉与注入

- **注入**：NFKC 归一化 + 零宽剥离，中英双语规则，单条高危或两条中危组合即拦截；命中的规则名写进回复。
- **间接注入**：工具返回内容一律包成 `<untrusted>`；备注字段落库前先过护栏，含指令内容直接拒绝。
- **幻觉**：回复模板只引用工具返回值；`checkGroundedness()` 可校验回复中的每个金额是否出现在工具结果里。
- **不可执行**：模型提出的工具调用走同一套 `ToolRegistry`，没有旁路。

## 身份与令牌

服务端**不认识"你说你是谁"，只认令牌**。

```bash
# 1. 登录换令牌（演示账号 PIN 123456）
curl -X POST http://127.0.0.1:8787/api/login \
  -H 'Content-Type: application/json' \
  -d '{"userId":"u_1001","pin":"123456"}'
# → {"token":"eyJzdWIiOiJ1XzEwMDEi...","expiresIn":1800}

# 2. 之后每个请求都带 Authorization: Bearer <token>
curl -X POST http://127.0.0.1:8787/api/chat \
  -H 'Authorization: Bearer <token>' \
  -H 'Content-Type: application/json' \
  -d '{"text":"查一下余额"}'
```

| 机制 | 行为 |
| :--- | :--- |
| 令牌签名 | HMAC-SHA256，无状态；改一个字符就失效 |
| 有效期 | 30 分钟（`SESSION_TTL_MS` 可调），过期返回 401 |
| 身份绑定 | 后端从令牌取 userId，忽略请求体；两者不一致返回 403 |
| PIN 存储 | scrypt 加盐派生，库里只有 64 位哈希 |
| 撞库防护 | 同一用户连续 5 次失败锁 60 秒（429） |
| 渠道 | 配置 `WEBHOOK_SECRET` 后，webhook 必须带 `x-webhook-secret` |

演示账号：`13800000001 / 123456`（张伟）。也可以在页面直接注册新用户，新账号自动获得 ¥1,000 开户演示资金。

### 注册与收款人

```bash
# 注册（自动登录，返回令牌）
curl -X POST http://127.0.0.1:8787/api/register \
  -H 'Content-Type: application/json' \
  -d '{"name":"赵六","phone":"13922223333","pin":"654321"}'

# 添加收款人（行内手机号会自动关联账户）
curl -X POST http://127.0.0.1:8787/api/contacts \
  -H 'Authorization: Bearer <token>' \
  -H 'Content-Type: application/json' \
  -d '{"name":"王小明","phone":"13800000003"}'
```

注册校验：姓名 2–20 字、手机号 11 位、PIN 6 位数字、手机号唯一；重复注册返回 409。新用户没有收款人时，转账会被追问而不是随便找人转。

## 已知限制

1. MFA 是演示实现（本地生成验证码），未接真实短信/人脸 SDK。
2. 账本是 Mock 复式记账，未对接真实核心系统。
3. 单进程内存会话，未做多实例会话共享。
4. 意图解析覆盖 6 类，长对话意图漂移未量化。
5. 汇率等外部服务尚未接入（下一步）。
