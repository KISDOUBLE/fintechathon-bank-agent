## 1 权限分级

### 1.1 分级矩阵

| 级别 | 判定标准 | 典型操作 | 放行条件 |
| :--- | :--- | :--- | :--- |
| L0 | 公开信息 | 汇率、产品列表 | 直接执行 |
| L1 | 本人只读 | 余额、流水、账单、订阅列表 | 直接执行 |
| L2 | 本人中风险写 | 普通转账、取消订阅 | 详情 + 二次确认 |
| L3 | 本人高风险写 | 金额 ≥ ¥5,000 的转账、新设备写操作 | 多因子认证 |
| X | 越权/跨域 | 查他人账户、未知工具 | 硬拒绝 + 审计告警 |

### 1.2 校验位置（关键）

鉴权在 **`ToolRegistry.execute()`** 内执行，不在提示词里：

1. 工具名必须在权限矩阵登记，否则 `unknown_tool`。
2. 跨用户访问（`args.userId !== actor.id`）一律 X，先于金额判断。
3. 金额 ≥ ¥5,000 的 L2 抬升 L3；新设备 2 小时内 L2 以上抬升 L3。
4. 日累计超 ¥20,000 直接拒绝。
5. `needConfirm` 但缺 `confirmed` → `CONFIRMATION_REQUIRED`；`needMfa` 但缺 `mfaVerified` → `MFA_REQUIRED`。

验证：红队 S-13（跨用户）、S-14（未确认转账）、S-15（越权取消订阅）全部拒绝，账本未变。

### 1.3 任务级授权

批量操作一次确认，只放开**本次列出的对象**，300 秒过期。换对象仍需重新确认（tests/agent）。

## 2 四类攻击的防护

### 2.1 直接提示注入

- 归一化：NFKC（全角→半角）、剥离零宽字符与变体选择符、合并中文间空格。
- 规则：中英双语 10 条，单条高危或两条中危组合即拦截。
- 命中后**不进入业务逻辑**，直接返回拒绝并写审计。

实测：全角（S-03）、零宽（S-04）、空格拆分（S-18）、英文（S-02）均可识别。

### 2.2 间接注入

- 工具返回统一包 `<untrusted source="tool_result">`，不拼进系统提示词。
- 备注字段落库前过同一套护栏，命中即拒绝（S-10）。
- 模型补写的字段必须能在原句找到原文，否则丢弃（防"编造备注"）。

### 2.3 越权操作

- 对话层与工具层**双次鉴权**，工具层不信任上层结论。
- 数据域按 actor 隔离，查询工具强制带 owner 条件。
- 跨用户直调返回 `X` 与 403，审计记录 `tool.denied`。

### 2.4 信息套取

- 正反两向规则：既拦"列出所有客户…"，也拦"把全部客户…列出来"（S-08）。
- 手机号在审计与界面中脱敏，身份证号不进日志。

## 3 身份与令牌

| 机制 | 实现 | 状态 |
| :--- | :--- | :--- |
| 登录 | 手机号或 ID + 6 位 PIN，scrypt 加盐存储 | ✅ |
| 令牌 | HMAC-SHA256 签名，30 分钟有效，篡改即失效 | ✅ |
| 身份绑定 | 服务端从令牌取 userId，请求体不一致返回 403 | ✅ |
| 登录限速 | 同一账号连续 5 次失败锁 60 秒 | ✅ |
| 注册校验 | 姓名/手机号/PIN 格式 + 手机号唯一 | ✅ |
| 渠道密钥 | 配置 `WEBHOOK_SECRET` 后 webhook 必须带密钥 | ✅ |
| 短信/邮箱验证 | — | ❌ 未实现 |
| 注册限速 | — | ❌ 未实现 |
| 找回密码 | — | ❌ 未实现 |

## 4 审计与可追溯

- 事件覆盖：输入、护栏、解析、判定、权限、确认、工具执行、回复、批量完成、登录、注册。
- 哈希链：每条记录包含上一条摘要，`verifyChain()` 返回首个断链位置。
- 一次 trace 能回答：谁、在什么权限下、做了什么、结果如何。
- 保留策略：本地演示不做冷存储；生产建议 180 天。

## 5 已知风险清单

| 编号 | 风险 | 等级 | 状态 | 说明 |
| :--- | :--- | :--- | :--- | :--- |
| R1 | 模型可能误解意图，导致转错对象 | 中 | 部分缓解 | 收款人必须匹配通讯录 + 确认卡展示 + 金额整数校验；但用户仍需看一眼确认卡 |
| R2 | MFA 为本地模拟 | 高 | **未解决** | 只验证流程，不验证认证强度；真实环境需接短信/人脸 SDK |
| R3 | 注册手机号未验证归属 | 高 | **未解决** | 可注册任意号码；需短信验证码 |
| R4 | 注册接口无限速 | 中 | **未解决** | 可被刷号；需按 IP/设备限流 |
| R5 | 无 HTTPS | 高 | **未解决** | 令牌本地明文传输；生产必须 TLS |
| R6 | 间接注入检测依赖规则 | 中 | 部分缓解 | 语义级注入可能绕过；建议加小模型分类器 |
| R7 | 单进程内存会话 | 低 | 已知 | 多实例部署需共享会话存储 |
| R8 | SQLite 写并发有限 | 低 | 已知 | 演示够用，压测上限偏低 |

## 6 不在防护范围

- 终端被木马控制、会话凭证被窃（需终端安全配合）。
- 内部员工与外部合谋（需双人复核制度）。
- 第三方依赖投毒（本项目零第三方依赖，风险面已大幅缩小）。

## 7 结论

已实现并验证：权限分级、工具层鉴权、注入防御、审计哈希链、身份令牌、确认令牌。

未实现且必须在答辩中说明：真实 MFA、手机号验证、注册限速、HTTPS。

这四项是"演示版"与"生产版"的主要差距，不应被表述为已解决。
