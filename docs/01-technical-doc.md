## 1 一句话定位

把自然语言指令转换成**受权限约束的银行操作**：大模型负责理解与提议，资金动作由确定性代码执行。

三个角色的边界：

- **规划层**用大模型，产出意图与参数，看不到凭证，发不起交易。
- **执行层**用普通代码，逐条判定权限、二次校验、执行、回滚。
- **审计层**记录每一次判定，任何历史决策都能按 trace 复原。

## 2 赛题要求与覆盖

赛题要求至少 3 个场景，三项硬门槛，加上渠道触达。当前覆盖：

| 要求 | 实现 | 代码位置 |
| :--- | :--- | :--- |
| 智能转账 | 姓名/别名/手机号收款、口语金额、多轮补金额、定时转账、AA 平摊 | `transfer_create` / `transfer_schedule_*` / `transfer_split` |
| 账单分析 | 分类汇总、占比、Top 商户、异常交易 | `bill_analyze` |
| 理财操作 | 产品列表、按风险推荐、申购、赎回（按天计息） | `wealth_*` |
| 卡片管理 | 列表、虚拟卡申请、日限额、交易限制/解锁、挂失/解挂 | `card_*` |
| 订阅代扣 | 列表、到期提醒、单条/批量取消、流水识别周期扣费 | `subscription_*` |
| 跨场景联动 | 生日：锁定预算、提前 2 天预订鲜花蛋糕、安排查询 | `birthday_setup` / `event_list` |
| 意图理解与规划 | 规则解析 + 模型兜底；多步计划（列目标→逐条判定→确认→执行） | `src/agent/parser.mjs`、`loop.mjs` |
| 权限分级 | L0–L3 + X，红色判定自动抬到强验证 | `src/core/permissions.mjs` |
| 安全机制 | 注入防御、幻觉防护、审计哈希链、确认令牌、身份令牌、熔断 | `src/core/guard.mjs`、`audit.mjs`、`src/auth/session.mjs` |
| 渠道 | Web 页面 + webhook JSON | `src/server.mjs`、`src/channels/webhook.mjs` |

六个场景全部覆盖。按备注转账是**策略性拒绝**：备注可伪造，不能作为身份依据。真实 MFA、手机号验证、HTTPS 仍未实现，见第 7 节。

## 3 架构

```
渠道（Web / webhook）
  → 接入层      登录令牌校验，确定 actor（不信任请求体）
  → 输入护栏    NFKC 归一化 + 零宽剥离 + 注入规则
  → 意图解析    规则优先；置信度 < 0.6 才调用模型；模型只产出结构
  → 三色判定    纯函数，只读快照，输出 rule + detail
  → 权限分级    L0/L1/L2/L3/X，金额与设备上下文抬升
  → 人工确认    L2 二次确认；L3 多因子；确认令牌一次性
  → 工具层      再次鉴权 + 参数校验 + 复式记账 + 幂等
  → 审计        结构化事件 + 哈希链
```

两条硬约束：

1. **模型不持有凭证**，所有资金动作经 `ToolRegistry.execute()`。
2. **鉴权在工具层再判一次**，上层说"已确认"不算数，缺少 `confirmed` / `mfaVerified` 证据照样拒绝。

## 4 核心实现

### 4.1 金额：整数分

全链路只用整数分，禁止浮点。

- 入口 `parseAmountToCents()` 支持 `5000`、`5,000`、`￥5,000.00`、`五千块`、`1.5万`、`5千`。
- 浮点入参直接抛错；不足一分、负数一律判无效。
- 展示层 `formatCents()` 统一两位小数。

### 4.2 意图解析：规则优先，模型兜底

6 类意图 + 兜底：`query_balance`、`transfer`、`bill_analyze`、`subscription_list`、`subscription_cancel`、`subscription_cancel_all`、`fx_quote`。

- 规则命中直接给高置信度，不调模型（离线可跑）。
- 置信度 < 0.6 时调用 `deepseek-flash` 做分类，**只返回 JSON 结构**；金额非整数分则丢弃，模型补的备注必须能在原句找到原文，否则视为编造丢弃。
- 安全网：句中出现"所有/全部/都"且涉及订阅时，即使模型判成单条也强制升级为批量。

### 4.3 三色判定：颜色是执行策略，不是"拒/不拒"

颜色语义严格对齐赛题：

| 颜色 | 含义 | 系统行为 |
| :--- | :--- | :--- |
| 绿 | 纯查询 | 直接执行 |
| 黄 | 日累计 ≤ ¥1,000 的资金操作 | 展示详情 + 二次确认 |
| 红 | 日累计 > ¥1,000 | **多因子认证后放行**，不是拒绝 |
| 硬拦截 | 越限、越权、注入、熔断 | 直接拒绝，不给验证机会 |

`assessRisk()` 是纯函数，只读快照，不写数据库。规则：

| 维度 | rule | 阈值 | 颜色 |
| :--- | :--- | :--- | :--- |
| 日累计额度内 | `R-AMT-YELLOW-CONFIRM` | 加本笔后 ≤ ¥1,000 | 黄 |
| 日累计超额 | `R-AMT-RED-VERIFY` | 加本笔后 > ¥1,000 | 红（强验证） |
| 单笔硬上限 | `R-LIMIT-SINGLE-BLOCK` | ≥ ¥50,000 | 硬拦截 |
| 日累计硬上限 | `R-LIMIT-DAILY-BLOCK` | > ¥20,000 | 硬拦截 |
| 首次收款人 | `R-PAYEE-FIRST` | ≥ ¥500 | 黄 |
| 可逆性 | `R-IRREVERSIBLE` | 转账/取消订阅 | 黄 |
| 频次 | `R-FREQ-10M-WARN` | 10 分钟 > 3 笔 | 黄 |
| 频次 | `R-FREQ-24H-BLOCK` | 24 小时 > 5 笔 | 硬拦截（熔断） |
| 终端 | `R-DEVICE-NEW` | 新设备 2 小时内 | 黄 |

颜色取最高严重度；`detail` 必须写清金额或次数，例如：

> 当日已转出 ¥500.00，加本笔共 ¥5,500.00，超出 ¥1,000.00 免强验证额度，需多因子认证

### 4.4 权限分级

| 级别 | 判定 | 放行条件 |
| :--- | :--- | :--- |
| L0 | 公开信息 | 直接执行 |
| L1 | 本人只读 | 直接执行 |
| L2 | 本人中风险写 | 展示详情 + 二次确认 |
| L3 | 本人高风险写 | 多因子认证 |
| X | 越权/跨域 | 硬拒绝 + 审计 |

抬升规则：判定为红色时按 L3（多因子）；新设备 2 小时内的 L2 以上按 L3；日累计超硬上限直接拒绝。

### 4.5 异常熔断

| 触发 | 阈值 | 动作 |
| :--- | :--- | :--- |
| 连续失败 | 10 分钟内 3 次（注入命中、工具失败、验证码错误） | 会话锁定 5 分钟，审计写 `circuit.open` |
| 高频转出 | 24 小时 > 5 笔 | 判定硬拦截 |
| 登录失败 | 同一账号连续 5 次 | 锁定 60 秒 |
| 验证码错误 | 同一确认令牌 3 次 | 作废令牌 |

### 4.6 多步计划与任务级授权

以"把自动续费全取消"为例：

1. L1 工具列出生效订阅（自动执行）
2. 逐条风险判定与权限预判（只读）
3. 一次性确认，换取**限定对象 + 限时 300 秒**的授权 `grant.scopeIds`
4. 逐条执行，单条失败不影响其余
5. 汇总并写 `batch.completed` 审计

授权只覆盖本次列出的订阅 ID，换一个 ID 仍需确认。

### 4.7 复式记账

- 每笔交易生成借贷两条分录，`SUM(delta_cents) = 0` 在事务内校验。
- 幂等键 = hash(traceId + stepId)，重复提交不重复扣款。
- 余额不足、跨用户、自转账均在事务内拒绝并回滚。

### 4.8 审计

每次请求记录事件流：`input.received → guard.blocked? → intent.parsed → risk.assessed → permission.decided → confirm.requested → tool.executed → reply.sent`。

- 每条记录含上一条哈希，`verifyChain()` 可定位断链位置。
- 手机号脱敏后入库，PIN 不落日志。

## 5 安全设计

| 威胁 | 防护 | 验证 |
| :--- | :--- | :--- |
| 直接注入 | NFKC + 零宽剥离 + 空格合并 + 双语规则 | S-01~S-06、S-11、S-18 |
| 间接注入 | 工具返回包 `<untrusted>`；备注落库前过护栏 | S-07、S-10 |
| 信息套取 | `G-EXFILTRATE` 正反两向规则 | S-08、S-17 |
| 越权调用 | 工具层独立鉴权，跨用户一律 X | S-13~S-15 |
| 社工施压 | "别问/免确认"单列高危；紧急话术单独标记 | S-06、S-12 |
| 身份冒用 | Bearer 令牌 + HMAC 签名 + 身份绑定 | tests/auth |
| 重放 | 确认令牌一次性 + 5 分钟过期 | tests/agent |
| 幻觉 | 回复模板只引用工具返回值；金额 groundedness 校验 | llm-test |

## 7 已知限制

| 编号 | 限制 | 影响 | 现状 |
| :--- | :--- | :--- | :--- |
| K1 | 核心银行是 Mock 复式记账 | 不证明真实核心对接 | 设计如此 |
